# botfp — бот автовыдачи для FunPay

Продавец загружает товар в базу, бот сам выдаёт его покупателю сразу после
оплаты, ведёт учёт остатков и вежливо отвечает на вопросы в чате.

## Что бот делает

- **Автосоздание объявлений.** Лоты описаны в конфиге — бот заводит их на
  FunPay сам и дальше держит в актуальном виде.
- **Автовыдача.** Пришёл оплаченный заказ — покупатель получает товар за пару секунд.
- **Два типа товара.** Уникальный (аккаунт, ключ — списывается при продаже) и
  безлимитный (гайд, ссылка, файл — уходит всем покупателям).
- **Снятие с витрины при нуле остатка** и возврат после пополнения, чтобы
  покупатель не оформлял заказ на то, чего нет.
- **Выдача ровно один раз.** Заказ не может быть выдан дважды, одна единица
  товара не может уйти двум покупателям — даже если FunPay пришлёт событие
  повторно или бот упадёт посреди отправки.
- **Вежливые команды** в чате: наличие, список лотов, повтор выдачи, вызов живого продавца.
- **Уведомления продавцу**, когда товар заканчивается или выдача сорвалась.

## Чего бот не делает

**Он не регистрирует аккаунты Roblox.** Этой части здесь нет намеренно:
автоматическая регистрация требует обхода антибот-защиты Roblox, прямо
запрещена их правилами, а массовые боты на детской платформе — основной
материал для скама и спама. Бот работает со складом, который вы наполняете
сами: `botfp stock add`. Откуда взялся товар — ответственность продавца.

## Установка

```bash
git clone <репозиторий> && cd botfp
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt          # нужен Python 3.11+
```

Ядро бота (склад, учёт, команды) работает на одной стандартной библиотеке.
Внешняя зависимость нужна только для подключения к FunPay.

## Два типа лота

От типа зависит, откуда бот берёт товар. Это главное, что нужно понять перед
настройкой.

| | `kind = "unique"` | `kind = "unlimited"` |
|---|---|---|
| Примеры | аккаунт, ключ, промокод | гайд, ссылка, конфиг, пак |
| Откуда товар | склад: `botfp stock add` | поле `payload` в конфиге |
| Списывается при продаже | да | нет |
| Может кончиться | да | нет |
| Снимается с витрины при нуле | да | не бывает нуля |

Уникальному лоту нельзя задать `payload` в конфиге, безлимитному — нельзя
грузить склад. Конфиг это проверяет и скажет, если перепутать.

## Настройка

```bash
python3 -m botfp init        # создаст config.toml из шаблона
```

Заполните в `config.toml`:

| Поле | Что это |
|---|---|
| `funpay.golden_key` | cookie вашей сессии FunPay (F12 → Application → Cookies) |
| `funpay.user_agent` | User-Agent того же браузера — иначе сессия чаще слетает |
| `bot.admins` | ваши ники на FunPay: им идут уведомления и доступны `!стат`, `!ожидают` |
| `lots[].id` | внутренний ключ лота, он же в `stock add --lot` |
| `lots[].match` | подстроки названия лота: FunPay присылает в событии только текст заказа, без id |
| `lots[].kind` | `unique` или `unlimited` — см. таблицу выше |
| `lots[].payload` | для безлимитных: что уходит покупателю (или `payload_file`) |
| `lots[].instructions` | что дописать к выдаче (инструкция по входу) |
| `lots[].listing` | секция объявления: `node_id`, `price`, `short_description` |

`golden_key` лучше не писать в файл, а передавать через окружение — оно имеет приоритет:

```bash
export FUNPAY_GOLDEN_KEY='...'
```

**Проверьте `match` на реальном названии лота.** Если описание заказа не
совпадёт ни с одним правилом, бот не станет гадать — он напишет вам, что
заказ нужно выдать вручную.

## Объявления на FunPay

```bash
python3 -m botfp lots sync            # сухой прогон: покажет план, витрину не тронет
python3 -m botfp lots sync --apply    # применить
python3 -m botfp lots list            # какой лот к какому объявлению привязан
python3 -m botfp lots refresh         # снять пустые лоты с витрины, вернуть пополненные
```

`lots sync` по умолчанию **ничего не меняет** — сначала показывает, что
сделает. Витрина магазина слишком заметная вещь, чтобы править её вслепую.

Чтобы бот синхронизировал витрину сам при запуске, поставьте в конфиге
`sync_listings_on_start = true`. Первый раз всё же пройдите руками с `--apply`.

### Нужен один лот-образец в каждой подкатегории

FunPay задаёт свой набор полей для каждой подкатегории, и они заметно
различаются. Бот не выдумывает форму вслепую: он **копирует её с вашего
существующего лота** в той же подкатегории и меняет название, описание, цену
и количество.

Поэтому порядок такой: заведите в подкатегории **один** лот руками — дальше
бот создаст по его образцу сколько угодно. Если образца нет, `lots sync`
честно скажет об этом и ничего не создаст.

### Дубликаты

Повторная синхронизация не плодит лоты. Два рубежа:

1. Таблица `lot_links` помнит, какому лоту из конфига какое объявление
   соответствует, — повторный прогон обновляет его.
2. Если связи нет (первый запуск, потеря базы, лот заведён руками), бот
   ищет среди существующих объявлений подходящее по названию и подкатегории
   и **привязывается** к нему. Создаёт — только если ничего не нашлось.

## Использование

```bash
# Пополнить склад: одна строка файла — одна единица товара.
# Дубликаты и пустые строки отсеиваются молча.
python3 -m botfp stock add --lot starter --file items.txt
cat items.txt | python3 -m botfp stock add --lot starter --file -

python3 -m botfp stock count      # остатки
python3 -m botfp stats            # остатки + сводка по выдачам
python3 -m botfp pending          # заказы, которые требуют внимания
python3 -m botfp retry 1003       # повторить выдачу заказа
python3 -m botfp retry --all      # повторить все зависшие
python3 -m botfp release 1003     # вернуть товар на склад (возврат/отмена)

python3 -m botfp run              # боевой запуск
python3 -m botfp run --console    # прогон в терминале, без FunPay
```

Консольный режим — способ посмотреть на бота, не подключая аккаунт:

```
botfp> order 1001 bob starter     # сымитировать оплаченный заказ
botfp> msg bob !наличие           # сымитировать сообщение покупателя
botfp> quit
```

## Команды в чате

| Команда | Кому | Что делает |
|---|---|---|
| `!помощь` | всем | список команд |
| `!наличие` | всем | остатки по лотам |
| `!товары` | всем | список лотов |
| `!повтор` | всем | прислать последний заказ ещё раз |
| `!человек` | всем | позвать продавца |
| `!стат` | продавцу | склад + статистика выдач |
| `!ожидают` | продавцу | зависшие заказы |

Работают и латинские синонимы (`!help`, `!stock`, `!repeat`), и префикс `/`.
На обычный текст бот здоровается **один раз на чат** и дальше молчит, чтобы
не влезать в вашу переписку с покупателем.

## Как устроена надёжность выдачи

Главный риск автовыдачи — отдать один аккаунт двум покупателям или списать
товар, не доставив его. Здесь это закрыто так:

1. **Резервирование в одной транзакции.** Выбор товара и запись заказа идут
   внутри `BEGIN IMMEDIATE`, поэтому два процесса не могут забрать одну единицу.
2. **Заказ — ключ идемпотентности.** `order_id` уникален в таблице выдач.
   Повторное событие о том же заказе не выдаёт второй товар.
3. **Порядок «зарезервировал → отправил → списал».** Если бот умрёт между
   шагами, товар останется закреплён за этим заказом, и следующая попытка
   отправит **то же самое**, а не новое.
4. **Ошибка отправки не возвращает товар на склад.** Сообщение могло дойти —
   вернуть товар значило бы рискнуть выдать его второму покупателю. Заказ
   попадает в `botfp pending`, продавец решает: `retry` или `release`.
5. **Что ушло — то записано.** У безлимитных лотов текст выдачи сохраняется в
   самом заказе. Поменяли ссылку в конфиге — старые заказы помнят прежнюю, и
   `!повтор` пришлёт ровно то, что покупатель получал.

## Безопасность

- `golden_key` — это полный доступ к аккаунту FunPay. Не коммитьте его.
- **В базе лежит товар в открытом виде** — иначе его нельзя выдать. Бот
  создаёт файл базы с правами `0600`; держите его на своём диске и не кладите
  бэкапы туда, куда есть доступ у посторонних.
- `config.toml` и `*.db` уже в `.gitignore`.

## Про лот за 1 рубль и отзывы

Просьба об отзыве идёт **после** выдачи и ни на что не влияет: покупатель
получает товар целиком независимо от того, оставит он отзыв или нет.
Отключается в конфиге: `ask_for_review = false`.

Не привязывайте выдачу или её полноту к оценке — это нарушение правил
площадки и быстрый путь к блокировке магазина.

## Структура

```
botfp/
  config.py            конфиг, типы лотов, сопоставление заказа с лотом
  db.py                схема SQLite, миграции и транзакции
  stock.py             склад и журнал выдач — здесь вся логика идемпотентности
  listings.py          синхронизация витрины FunPay с конфигом
  delivery.py          заказ -> склад -> сообщение покупателю
  commands.py          разбор команд из чата
  templates.py         все тексты сообщений
  transport.py         контракт площадки + консольная реализация
  funpay_transport.py  адаптер к FunPay (FunPayAPI)
  bot.py               главный цикл
  cli.py               командная строка
```

Логика бота не знает, что она работает с FunPay: всё общение с площадкой
спрятано за `Transport`. Поэтому её можно целиком прогнать в тестах и в
консоли, не трогая боевой аккаунт.
